# 0010 · 循环预算：数什么、什么形态、非法值怎么办

> 原来在 `src/domain/loop.ts` 文件头（106 行注释 / 243 行文件）。2026-09 外移。

## 背景

主循环里决定「还要不要再转一圈」的是模型自己，而**模型是概率性的** ——
没有任何东西保证它会在有限步内说「我说完了」。

**轮次上限是这个循环里唯一一个不依赖模型配合的终止保证。**

## 候选与决定

```text
① 数什么
   选择   ★两个独立上限★：模型调用次数、工具执行次数
   理由   一次响应可以并行要求多个工具，两个数字差得很远
          （5 次响应 × 每次 3 个工具 = 5 vs 15）
          按模型调用数防的是★花钱★，按工具执行数防的是★副作用★
   代价   调用方要配两个数，也要处理两种「撞上限」

② 形态
   候选   谓词（canCall? / canRun?） vs ★状态转换★
   选择   状态转换：吃一个 LoopBudget，吐一个新的 LoopBudget
   理由   ★谓词可以被忘记调用，状态转换不能★ ——
          你要拿到下一个 state，就必须经过这里，计数是它的副产品
   对照   turn.ts 的 decide 反过来选了谓词，理由见 ADR 0006 §⑥：
          loop 是循环★里的一步★，decide 是循环的★出口★，出口拦不住不肯走的人

③ 上限值非法怎么办
   选择   ★构造时校验一次，之后不再校验★（smart constructor）
   合法   安全整数且 >= 1 —— 一条判据同时挡掉
          0 / 负数 / 小数 / Infinity / NaN / 超出安全整数范围
   顺序   两个都非法时只报第一个（model-calls 优先）
   代价   修完第一个才会发现第二个也错

④ 预算不够是 ok 还是 err
   选择   ★err★。预算不够意味着「这个动作不能做」，调用方必须改变行为 ——
          放进错误分支，类型系统会强迫它处理，忽略不了
   代价   调用方每次都要 if (!r.ok)
   载荷   错误里带 used / max —— 收尾时要告诉用户「跑了 N 轮，上限 N」

⑤ 错误里带不带出错的值
   选择   ★带★（InvalidLimit.value、InvalidCount.value）
   ⚠     这和 path.ts 的结论★相反★，但判据是同一条：★值从哪来★
            path：来自模型/用户 → 进日志就是把攻击载荷原样落盘 → 不带
            这里：来自自己的配置和自己的适配器 → 带上才好排错 → 带

⑥ 一次要跑 N 个工具，但额度只剩 M < N 个
   选择   ★全拒绝，一个都不跑★（原子性）
   理由   领域层只能返回一个状态，做不了「部分执行」；
          而部分执行会留下★一半的副作用★，比浪费额度难收拾
   代价   剩 2 个额度时来了 3 个工具请求，那 2 个额度就浪费了

⑦ 给后面的阶段留位置
   选择   ★只留「加字段是便宜的」，不提前加参数★
   理由   大小上限、终止条件进来时，是往 LoopBudget / LoopLimits 各加一个
          字段 —— 双向门。
          现在就把 AbortSignal 塞进签名是现在付成本、收益在两阶段之后，
          而且它★可变、绑事件循环★，会让这个函数不再是纯函数
```

## SAFETY

**必须用 `Number.isSafeInteger` 而不是 `isInteger`。**

```text
Number.isInteger(2**53)      → true
2**53 + 1 === 2**53          → true      ← ★计数器加不上去★
```

计数器加不上去 = 循环永远到不了上限 = **正是这个模块要防的事**。
