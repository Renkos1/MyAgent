# 0015 · 取消的那一格要不要分「跑没跑过」

> **本文取代 [0014](./0014-tool-outcome-aborted.md) §②。**
> 0014 §① ③ 不变 —— 取消仍然不是失败，契约仍然按那个办法摆。

## 背景

0014 §② 当时的决定是**只加一格、不带 `sideEffect`**，并写了一条期限：

> ⏰ 阶段 7 第一次把 outcome 写进库之前必须重新考虑。
> 过了那一刻，代码成本不变，数据成本变成无穷。

现在在期限之内回来兑现它。**这不是推翻 0014，是 0014 按设计运转了一次** ——
带期限的「暂不决定」和「忘了决定」的区别就在这里：前者会自己回来。

促成现在动手的是阶段 3 的两件事：

```text
契约套件建起来了   LlmPort 那边早就把取消拆成两个场景
                   （aborted-before-send / aborted-mid-flight），
                   ToolPort 这边却只有一格 —— ★同一个概念两种形状★
eval 层建起来了     成绩单要写进 Git（0013 §③）。
                   outcome 进磁盘的第一天已经到了，不是阶段 7
```

## 候选与决定

### ① 分不分，分成几格

```text
候选   a  不分（0014 §② 的现状）
       b  ★两格：none / unknown★
       c  三格：none / happened / unknown
       d  两个 kind：aborted-before / aborted-during

判据   ★「调用方拿它做什么决定」——★ 三个问题，答案完全一致：
         重试安全吗？    没跑过 → 安全；跑过一半 → ★不安全★
         要不要记账？    没跑过 → 不记；跑过一半 → ★可能已经计费★
         跟模型怎么说？  没跑过 → 「没执行」；跑过一半 → 「不知道」
       三个问题都只取决于★副作用发生了没有★ ⇒ 这就是该建模的那个轴

选择   b
       c 出局：★happened 这一格永远填不出来★ ——
         真知道跑完了、副作用确定发生了，那就不该返回 aborted，该返回 ok。
         留一个填不出来的格子，迟早有人往里填猜测
       d 出局：kind 是给调用方分派用的，两种取消的分派逻辑★是同一套★
         （都不记错误率、都不重试、都不说"工具坏了"），
         差别在于「之后能不能重来」—— 那是参数，不是分类
代价   适配器必须知道自己跑到哪一步了。
       ⚠ 对包一层 SDK 的适配器，这件事★不一定问得出来★ ——
         问不出来时唯一诚实的答案是 unknown（见 ②）
```

### ② 为什么第二格叫 `unknown` 不叫 `happened`

```text
选择   ★"none" | "unknown"★
判据   跑到一半被叫停时，我们★真的不知道★对面做完没有 ——
       请求已经发出去，文件可能已经写了一半，也可能一个字节都没落盘。
       写成 happened 是★假装知道★，而假装知道的方向恰好是最危险的那个：
       调用方会据此认为「肯定发生了，那就不用管了」

       ★这就是第三态★（ts-modern-train docs/MAP.md 图 6）。
       把「不知道」写进类型，调用方就★不可能★把它当成「没发生」处理 ——
       因为类型里根本没有「发生了」这个值可以对照

另外   ★sideEffect 说的是事实，不是意图。★
       FakeTools 的第一道检查因此必须在任何 await 和任何 push ★之前★ ——
       检查本身留了痕迹的话，none 就是句谎话
```

### ③ 喂回模型的文本要不要跟着分

```text
选择   ★分★：「[工具已取消，没有执行]」 / 「[工具已取消，是否已执行未知]」
判据   模型看不到 ToolOutcome，只看到这句话 —— ★它是模型唯一的信息来源★。
       两种取消说成同一句，前面所有的建模在最后一米被压平
代价   多一条契约要验。
       IMPORTANT: 契约套件里★必须单独一条★断言「两格的 sideEffect 不同」，
       不能只靠「摆得出这一格吗」那条 ——
       后者对一个把 sideEffect 写死成 unknown 的实现完全无感（实测：埋这个 bug 只红 3 条，
       而其中 2 条来自那条单独的断言）
```

### ④ 契约的格子和端口的 kind 不是一回事

```text
选择   ★ToolCase = Exclude<kind,"aborted"> | "aborted-before" | "aborted-during"★
判据   场景集是对★外面的世界★建模，kind 是压平之后的结果。
       一个 kind 底下藏着两种外部事实时，★场景要跟着世界走，不跟着类型走★
       —— LlmPort 那边早就是这么做的，这次只是补上一致性
代价   契约文件里多一个类型，且它和 ToolOutcome["kind"] 长得像但不相等。
       ⚠ 已在类型注释里明写「它不等于 kind」，因为这正是会看错的地方
```
