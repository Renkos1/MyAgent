# 0009 · 文本大小：用什么单位量、怎么切

> 原来在 `src/domain/size.ts` 文件头（75 行注释 / 124 行文件）。2026-09 外移。

## 背景

`size.ts` 只回答两个问题：这段文本有多大、怎么把它切到指定大小以内。
**它不认识 LoopBudget，也不 import loop.ts** —— 「切完之后预算怎么扣」是 `input.ts` 的事。

## 候选与决定

```text
① 上限用什么单位量
   候选   UTF-16 length / 码点 / 字素簇 / ★UTF-8 字节★
   判据   上限最终要和「落盘 / 过网络 / 进 Buffer」的数字对齐，
          ★只有字节是那个数字★
   实测   UTF-16 length 和字节能差 3 倍（中文），
          和字素簇能差 18 倍（ZWJ emoji）
   选择   UTF-8 字节
   代价   对用户说「限制 4096」时，中文只有约 1365 个字

   ⚠ measure 支持四种单位是为了★可观测★（日志里同时记几个数字），
     但★判上限只用 utf-8★。别让第二个单位偷偷变成判据。

② 超限了：拒绝还是截断
   选择   ★由调用方每次指定★（LimitMode）
   理由   读一个源文件截断是合理的；读一份配置截断就是错的 ——
          这个判断只有调用点知道
   代价   调用方每次都要选，★选错没人拦★

③ 截断在哪一刀
   选择   ★优先退到最近的换行；没有换行就退到最近的字素簇边界★
   理由   换行是语义边界，切出来的东西人还能读；
          字素簇边界保证永远不切碎一个字符
   代价   实际保留的字节数会小于上限，有时小很多（一整段没换行时）

④ 单个上限还是总和上限
   选择   ★两个都要，分工不同★
            单个（perItem） 防「一个大文件打死进程」—— 无状态的规则
            总和（total）   防「每个都不超但加起来超」—— 需要状态的规则
   所以单个在 size/input 判，总和在 loop.ts 的计数器上判

⑤ 空文本合法吗
   选择   ★本来就空 → 合法★（0 字节的文件是真实存在的东西）
          ★被截断成空 → 非法★（调用方要的是内容，给它空串等于骗它）
   这两者由 input.ts 区分，本模块只负责返回截断结果
```

## SAFETY

**绝不按 UTF-16 下标切。** 实测 `"报告：👨‍👩‍👧".slice(0, 4)` 会切出半个代理对，
转 UTF-8 时原字符变成 `U+FFFD`**永久丢失**。

## 后果

```text
✅ 品牌类型（Utf8Bytes / Utf16Units / CodePoints / Graphemes）让单位混不了
⛔ 截断的实际字节数不可预测（依赖换行位置）—— 测试只能断言「不超过上限」
   和「是合法的 UTF-8」，不能断言具体数字
```
